# Muhun MCSV Manager 正式自動更新與回復

## 使用方式

桌面程式的「程式設定」與手機 Web 總覽都可選擇 `stable` 或 `beta`，依序執行「檢查更新」→「下載並驗證」→「排程套用」。Web 操作只對 Owner 或具有全域 `update.manage` 權限的帳號顯示；Server 範圍權限不能升級成更新權限。

預設沒有假造的官方更新站。管理者必須在 Service 設定填入精確的 default-port HTTPS manifest URL、精確 DNS host allowlist 與本機 pinned public-key document。URL 不接受帳密、fragment、query、非 443 Port、萬用字元或未列入 allowlist 的 host。

```json
{
  "Updates": {
    "StableManifestUrl": "https://updates.example.com/mcsv/stable/update-manifest.json",
    "BetaManifestUrl": "https://updates.example.com/mcsv/beta/update-manifest.json",
    "AllowedFeedHosts": ["updates.example.com"],
    "PublicKeyDocumentPath": "C:\\Program Files\\Muhun\\MCSV\\update-signing-public-key.json"
  }
}
```

## 驗證順序

1. Service 使用無 Proxy、禁止自動 redirect、大小有界的 HTTP client 讀取 allowlisted HTTPS manifest 與 detached signature。
2. pinned RSA 3072+ 公鑰驗證原始 UTF-8 manifest 的 RSA-PSS-SHA256；版本、通道、產品 ID 與檔案清單必須符合正式契約。
3. ZIP 下載限制長度並驗證整包 SHA-256，接著逐 entry 驗證路徑、數量、大小與 SHA-256；任一額外、遺失、重複或 traversal entry 都會拒絕。
4. Service 產生短效、一次性的 HMAC activation request。Updater 只接受受管理資料根下固定目錄中的 GUID 檔名，不接受任意命令或輸出路徑。
5. Updater 啟動先復原任何中斷切換，再重驗 pinned key、manifest、package 與正式 GUI／Service／Updater entry point，才建立新版本目錄。

## A/B 套用與回復

套用只會切換版本化目錄與 `active-version.v1`，不就地覆寫現行版本。Windows Service 啟動後必須在時限內通過 loopback health check，而且 GUI 與 Service 檔案版本必須一致。健康檢查失敗時，Updater 會把 Service binary path、active pointer 與執行狀態回復到前一個已驗證版本；缺少可信回復點時會直接停止，不先切換。

發行腳本、測試與安裝程式都不會自動安裝憑證到 Windows 信任庫、不關閉 SmartScreen、不降低 PowerShell Execution Policy，也不執行正式安裝。
