# Muhun MCSV Manager 1.0 正式產品架構

更新日期：2026-08-27

## 執行模型

```text
手機瀏覽器／iOS PWA／Android APK
                 │ HTTPS
                 ▼
       受控 Tailscale Funnel
                 │ 只代理到 loopback
                 ▼
       Muhun MCSV Windows Service
       ├─ REST API v1／Web／事件更新
       ├─ Auth／RBAC／Session／Audit
       ├─ Server Runtime／Port／Console
       ├─ Backup／Modpack Update／Rollback
       ├─ Notification Outbox／Discord
       ├─ Provider Host／Registry／Trust
       └─ Product Update Coordinator
                 ▲
                 │ 具 ACL 的 Named Pipe IPC API 1.5
                 ▼
            Windows WPF GUI
```

Windows Service 是受管狀態的唯一寫入者。GUI、Web、PWA 與 APK 只傳送版本化要求；Service 重新驗證呼叫者、權限、Server scope、狀態與冪等鍵後才執行。Service 模式不會因 IPC 中斷而回退成 GUI 直接啟動 Java。

## 專案責任

- `MinecraftServerManager.Contracts`：API／IPC DTO、協定版本、權限、事件、本地化鍵與 Provider Manifest。
- `MinecraftServerManager.Core`：純 headless 的程序、Port、Console、備份、下載、圖片、安全路徑與模組包交易。
- `MinecraftServerManager.Data`：SQLite schema/migration、帳號、記住裝置、audit、sequence、通知 outbox 與 Windows DPAPI Vault。
- `MinecraftServerManager.Notifications`：通知 dispatcher、節流／重試及 Discord Provider。
- `MinecraftServerManager.ProviderHost`：簽署套件驗證、Publisher trust、獨立程序 RPC、能力與網路政策。
- `MinecraftServerManager.BuiltinProvider`：使用相同 Provider 協定的 Muhun 第一方目錄 Provider。
- `MinecraftServerManager.Service`：Windows Service lifetime、composition root、Server runtime、遠端 Web、通知、Provider、備份及更新協調。
- `MinecraftServerManager.Client`：Windows GUI 使用的版本化 Named Pipe 客戶端。
- `MinecraftServerManager.Remote`：loopback Web API、認證、PWA 與 responsive UI。
- `MinecraftServerManager.App`：WPF 呈現、Windows 使用者偏好、候選下載與安全遷移協調；不持有正式 Service 的 Java 程序。
- `MinecraftServerManager.Updater`：在 GUI 關閉且 Service 協調下完成產品 A/B 套用、健康檢查與回復。

## Windows Service 與資料目錄

- SCM 名稱：`MuhunMCSV`；顯示名稱：`Muhun MCSV Service`。
- 執行身分：虛擬服務帳號 `NT SERVICE\MuhunMCSV`，不是 LocalSystem，也不使用互動桌面。
- 本機 API 預設 Port：`39050`，只監聽 `127.0.0.1`。
- 安裝目錄：`%ProgramFiles%\Muhun\MCSV\versions\<version>`，由 `active-version.v1` 指向目前版本。
- 服務資料：`%ProgramData%\Muhun\MCSV`；GUI 個人偏好位於 `%LocalAppData%\Muhun\MCSV`。
- GUI 安全匯入只可寫入 Service 明確授權的 `imports` staging；Service 以 no-follow handle、大小／數量限制與 manifest hash 重新驗證後才接管。
- Preview 資料使用複本與提交式遷移；原始世界不就地修改，失敗不切換 registry。

ProgramData 內的主要責任目錄：

```text
%ProgramData%\Muhun\MCSV\
├─ data\          SQLite、registry、意圖與狀態
├─ secrets\       DPAPI 保護的秘密
├─ imports\       GUI 授權候選 staging
├─ servers\       Service 管理的 Server
├─ backups\       ZIP 與 pre-restore 恢復點
├─ updates\       驗證候選、一次性要求與 journal
├─ plugins\       已驗證 Provider 套件
└─ logs\           有界服務診斷
```

## API、IPC 與長時間工作

- REST 根路徑：`/api/v1`；IPC package：`muhun.mcsv.ipc.v1`。
- 1.x 只允許 additive change；breaking change 使用新的 protocol major。
- Client 與 Service 握手交換 min/max/current，沒有交集時拒絕 mutation。
- Console、狀態與玩家資料使用 sequence/cursor；慢客戶端只失去舊畫面樣本，不阻塞 Java stdout。
- 下載、匯入、備份與更新使用操作識別碼或有界 IPC，不長時間佔用 request reader。
- 錯誤採穩定 code/localization key/arguments；程式不解析翻譯字串判斷流程。

## 使用者、權限與稽核

權限採純授予、預設拒絕：

- Server scope：`server.*`、`console.*`、`player.*`、`backup.*`、`server.settings.*`。
- Global scope：`user.*`、`permission.manage`、`notification.*`、`provider.*`、`update.manage`、`audit.read`、`service.manage`。

未知權限、空 Server ID、global-only 權限放入 Server scope、或缺少 target 都會被拒絕。最後一位 Owner 不可刪除或停權。角色／權限改變會更新 security stamp，使現有 Session 與 remembered device 在下一次使用時重新套用最新權限。Audit 只保存穩定動作與必要中繼資料，不保存 PIN、Token、Webhook 或本機敏感路徑。

## 遠端 Web 與 HTTPS

Service 內嵌 Web Host 只綁 loopback。正式公開入口由 Service 擁有的一個 Tailscale Funnel 前景 session 提供：

- 只接受精確 HTTPS 443 root proxy 至固定 loopback Port。
- 啟動前後都解析 Tailscale status；既有衝突、未知 schema、間接或持久規則一律 fail closed，不覆寫使用者設定。
- Tunnel 中止、route 不符或 Service 關閉時，公開入口與 Session 一併撤除／撤銷。
- 不信任外部 identity header；仍須使用 MCSV 本機建立的帳號與最小權限。
- Cookie 為 Secure／HttpOnly／SameSite；mutation 同時要求精確 Origin、CSRF、RBAC 與 Idempotency-Key。
- PWA 離線頁不快取 API、狀態、憑證或 mutation，也不使用 Background Sync。

可攜相容模式仍保留 Tailscale Serve/Funnel、Cloudflare Named 與 Quick Tunnel 工具，但正式 Service 邊界不依賴變動的 Quick Tunnel 網址。

## 備份、模組包與產品更新

Service-owned backup 以 opaque ID 對 GUI/Web 顯示，不洩漏實體路徑。還原只允許完全停止的 Server，且先建立 pre-restore ZIP，再以受驗證的原子目錄交換套用。

模組包更新與產品更新是兩套獨立交易：

- 模組包：GUI 只下載官方候選並建立逐檔 manifest；Service 重驗來源與路徑、建立不覆蓋備份、套用候選、啟動並進行 Minecraft ready/status probe；失敗自動回復，crash 後依 journal 繼續。
- 產品：Service 從精確 allowlisted HTTPS host 取得 RSA-PSS 簽署 manifest，驗證版本／通道／RID、整包及逐檔 SHA-256，再由外部 Updater 安全解壓至新版本目錄。A/B 指標、SCM binary path 或健康檢查失敗時切回前一版。

## 通知與 Discord

控制台、程序、備份與更新只發出有界 domain event。事件先寫 SQLite outbox，再由 dispatcher 至少一次送出並記錄去重／重試狀態。含 password、secret、token、webhook、authorization 等敏感欄位的事件會在進入 outbox 前拒絕。

Discord Webhook 只保存在 DPAPI Vault；Provider 僅連線 Discord 官方 HTTPS host，禁止 redirect，限制 payload 與 timeout，對 429 尊重 Retry-After、對 5xx 有界退避、對永久錯誤停用並建立本機通知。

## Provider 擴充

Provider 不以任意 DLL 載入 Service。`.mcsvp` 必須通過 schema、SemVer、Plugin API major、逐檔 SHA-256、ECDSA P-256 發行者簽章、entry point 與 host allowlist 驗證後，才在獨立程序與 Windows Job boundary 內執行。RPC frame、輸出、時間與資源皆有上限；未知能力、wildcard/IP/port host、未宣告網路及任意 UI 內容預設拒絕。

## 多語言與外觀效能

WPF 與 Web 使用同一版本化 `zh-TW`／`en-US` key contract，語系可即時切換。WPF 所有正式 Window 共用深色資源與原生 HWND 深色 surface；DWM composition background、caption 與 `WM_ERASEBKGND` 路徑避免首幀、resize 或 UI 暫忙時露出白底。

Console 採 100 ms 批次、有界 queue 與單次 collection Reset；玩家資料 lazy-load 並取消過期要求，presence 合併，資源只保留最新樣本。這些界線使 Minecraft 大量啟動 log 不會逐行阻塞 WPF Dispatcher。

## 發行信任

正式 Windows 發行同時要求 Authenticode、RSA-PSS 更新簽章、Provider ECDSA 簽章與逐檔 SHA-256。Android APK 使用獨立長期簽章身分。私鑰只存在原始碼外的受限 ACL 目錄。

本機自簽憑證只能建立專案金鑰連續性，不等於公開 CA，也不繞過 SmartScreen；公開散發若需 Windows 預設信任，必須改用公開 Code Signing CA。完整發行流程見[正式產品簽章與安全發布](正式產品-簽章與安全發布.md)，逐項驗收見[第三最終階段 17 項驗收](正式產品-第三階段-Roadmap.md)。
