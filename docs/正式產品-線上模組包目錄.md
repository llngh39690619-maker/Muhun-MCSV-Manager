# 正式產品：線上模組包目錄與圖片契約

更新日期：2026-09-09

## 使用者介面

- 來源、排序、Minecraft 版本、模組載入器與來源分類都是實際查詢條件，不是只有外觀的按鈕。
- 結果以卡片顯示來源、名稱、作者、摘要、下載量、更新日期及預覽圖；單次最多呈現 20 筆，避免大量卡片同時解碼。
- Modrinth 支援 Fabric、Forge、NeoForge、Quilt 與其模組包分類；FTB 依官方版本資料在有界候選集合中篩選 Minecraft 版本與 Loader。FTB 未提供的分類不會在畫面上虛構。
- CurseForge 入口使用使用者自己的官方 API Key。Server 模組包更新在尚無保存值時可要求只供該次作業使用的 Key；Server 目錄與客戶端目錄共用同一個每使用者 DPAPI 憑證。保存值以 Windows DPAPI CurrentUser 密文存入受管理的每使用者 `ClientSecrets`，不回填密碼欄，也不進入 EXE、repository、一般設定、日誌或 Service IPC。
- 客戶端不顯示 API Key 輸入框。使用者只需在程式建立的一次性設定檔填入一行官方 Key 並存檔；回到 CurseForge 搜尋時會自動匯入並直接使用。成功時才原子取代既有加密憑證並清除明文匯入檔；匯入失敗不改動原憑證。
- 客戶端 CurseForge 目錄可經官方 API 搜尋、查看並直接安裝正式版本。可散布的根 ZIP 與 manifest 必要檔案都會由官方 API 取得、逐檔驗證並在隔離 staging 組裝；只有作者禁止第三方散布或根檔沒有官方 download-url 時，按鈕才改成經驗證的 CurseForge 官方專案頁。
- 每位 Windows 使用者與每台電腦應使用自己的 Key。X MCSV 不爬取 CurseForge 網頁、不繞過 API／授權或作者的第三方散布設定，也不重新託管檔案。

## 圖片與效能邊界

- 只接受各來源明確允許的官方 HTTPS 圖片主機；拒絕重新導向、非預設 Port、URI 帳密、格式偽裝與未知內容類型。
- 單張圖片上限 5 MiB、8192×8192 且最多 32 Mi pixels，同時下載最多 3 張。
- 網路下載、快取命中驗證與 WPF 解碼都不在 UI thread 進行。目錄卡只解碼到最高 480×270，且同時最多解碼 2 張，完成後凍結再交給畫面。
- 快取使用來源與 URI 的 SHA-256 key、暫存檔、flush 與原子提交；圖片失敗只退回文字縮寫，不影響模組包查詢或安裝。

## 安裝後的伺服器圖示

- 安裝成功後，來源代號、目錄圖示與預覽圖會寫入 Server 記錄。
- 遠端圖片不直接成為 Server 清單來源；管理器先離線解碼、縮放並轉為 Server 自有的 PNG，再原子寫入 `.mcsv/assets`。清單圖示最高 256 px，預覽圖最高 1280 px。
- 左側清單的優先順序為「使用者自訂 ICON → 模組包目錄 ICON → 原有核心字母」。因此使用者後續自訂的圖示不會被目錄資料覆蓋。
- 圖片是附加資訊；下載或解碼失敗時，已完成驗證的 Server 安裝仍保留並使用核心字母，不會留下失敗的半成品安裝。
- 上方選定的 Minecraft 版本與 Loader 也會套用到右側版本清單，避免從符合條件的卡片再選到不相容版本。

## Provider 查詢對應

| 畫面條件 | Modrinth | FTB | CurseForge（使用者 BYOK） |
|---|---|---|---|
| 搜尋文字 | 官方 Search `query` | 官方目錄搜尋 | 官方 Search `searchFilter` |
| 排序 | 官方 `index` | 有界資料排序 | 官方 `sortField`／降冪 |
| Minecraft 版本 | Search facet | 版本資料本機篩選 | `gameVersion` |
| Loader | Search facet | 版本資料本機篩選 | 官方 loader enum |
| 分類 | Search facet | 不顯示 | 官方 `categoryId` |
| 分頁 | `offset`／`limit` | 有界候選後切頁 | `index`／`pageSize` |

上表的 CurseForge 查詢條件同樣用於客戶端官方目錄瀏覽。版本載入會優先使用檔案 `gameVersions` 的明確 Loader，再使用專案 `latestFilesIndexes.modLoader` 的同檔或單一相容候選；歧義保持空白，不只憑 Minecraft 版本猜測。安裝時則以已驗證 ZIP 內的 primary loader 作最終權威，下載必要相依檔、安全套用 overrides，完成後才原子加入客戶端 registry。
