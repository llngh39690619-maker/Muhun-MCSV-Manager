版本：1.0.3 stable
適用系統：Windows 10／11 x64

發行包使用專案自簽憑證。它可證明檔案由同一專案金鑰簽署，但不是公開 CA，也不會自動取得 Microsoft SmartScreen 信譽。

## 2. 驗證正式包

在發行目錄外使用 PowerShell 7 執行：

```powershell
$release = 'C:\Users\Example\Documents\Codex\2026-08-14\new-chat\work\formal-release-output\Muhun-MCSV-1.0.3-final-20260827T170851'

& "$release\Test-MuhunMcsvRelease.ps1" `
  -ReleaseDirectory $release `
  -AndroidApkSignerPath 'C:\Users\Example\Documents\Codex\2026-08-14\new-chat\work\tooling\android-sdk\build-tools\36.0.0\apksigner.bat' `
  -AndroidAapt2Path 'C:\Users\Example\Documents\Codex\2026-08-14\new-chat\work\tooling\android-sdk\build-tools\36.0.0\aapt2.exe' `
  -AllowUntrustedSelfSigned
```

驗證器會重新讀取 RSA-PSS manifest、逐檔 SHA-256、ZIP 安全界線、六個直接 Authenticode 成品、Provider ECDSA 簽章及 Android v2／v3／v4。任何一項失敗都不要安裝。

`-AllowUntrustedSelfSigned` 只允許 manifest 已釘選的同一張自簽發布者憑證，不會忽略 hash、簽章、時間戳或檔案清單錯誤。

## 3. 安裝或由 1.0.0 升級

目前這台電腦上的正式 Service 仍是 1.0.0。只有執行以下管理員安裝流程後，Service、GUI 與 IPC 才會切換到 1.0.3；不要直接從發行目錄執行 Service／Updater EXE，也不要手動覆蓋 `%ProgramFiles%` 版本資料夾。

1. 先人工核對上列發布者憑證 SHA-256。
2. 以系統管理員身分開啟 PowerShell 7。
3. 信任發行目錄內的憑證：

```powershell
$release = 'C:\Users\Example\Documents\Codex\2026-08-14\new-chat\work\formal-release-output\Muhun-MCSV-1.0.3-final-20260827T170851'

certutil.exe -addstore -f Root "$release\publisher.cer"
certutil.exe -addstore -f TrustedPublisher "$release\publisher.cer"
```

4. 確認安裝器簽章，再執行安裝：

```powershell
Get-AuthenticodeSignature "$release\Install-MuhunMcsv.ps1" |
  Format-List Status, StatusMessage

Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned -Force
& "$release\Install-MuhunMcsv.ps1" -SourceDirectory $release
```

安裝器會驗證自己的 Authenticode、發布者、release／update manifest、所有檔案 SHA-256 及版本，然後建立或升級 `MuhunMCSV` Windows Service。安裝成功後從開始功能表開啟「Muhun MCSV Manager」；日常 GUI 不需要管理員權限。

預設位置：

```text
%ProgramFiles%\Muhun\MCSV\
├─ launcher\
├─ versions\1.0.3\
└─ active-version.v1

%ProgramData%\Muhun\MCSV\
├─ data\
├─ secrets\
├─ imports\
├─ servers\
├─ backups\
├─ updates\
├─ plugins\
└─ logs\

%LocalAppData%\Muhun\MCSV\   GUI 個人偏好與外觀資產
```

關閉 GUI 不會停止 Windows Service 所持有的 Minecraft Server、Web、通知或更新工作。

## 4. 為什麼資料夾、刪除、模組／插件或 Java 會停用

1.0.3 GUI 必須與支援 IPC API 1.5 的 1.0.3 Service 配對。若 GUI 連到目前仍安裝的 1.0.0 Service，握手版本不支援新命令，介面會刻意 fail closed，因此下列項目保持停用或無資料：

- 開啟資料夾
- 完全刪除 Server
- 模組／插件頁
- Java Runtime 頁

這不是靠單獨更換 GUI EXE 就能修正。請依上一節執行已簽署 1.0.3 安裝器，讓 Service 與 GUI 一起升級，再重新開啟 GUI。

安全邊界如下：

- 開啟真實資料夾與永久刪除只允許本機 GUI 經 ACL 保護的 Named Pipe 使用，不提供 Web／REST。
- 永久刪除會先封鎖自動重啟、清除執行意圖、安全停止 Java，再驗證 Service 管理的目錄及 no-follow 邊界；失敗會保留管理紀錄供重試。
- 模組／插件只讀取受管理 Server 頂層 `mods`／`plugins` 內的 JAR，頁籤開啟或手動重新整理時才掃描，且筆數、名稱及 metadata 有上限。
- Java 頁顯示 Service 註冊的版本、種類與架構；Web 不會得到 Service 實體路徑。
- Web／手機每次讀取都需通過登入及該 Server 的 `server.read` scope。

## 5. Server 管理

- 建立、匯入或線上安裝 Server 後，Java 程序由 Service 持有。
- 啟動時從 `25565` 起選擇當下最低可用 TCP Listener Port；`25565` 空閒就使用，真的被占用才改用 `25566` 以上。
- 按「選取」後才顯示 Server 核取方框；至少勾選一台後批次啟動／停止才啟用。
- Console 採有界 queue 與批次 UI 更新；錯誤／警告分流只在 Server 設定勾選後顯示。
- 玩家、模組／插件及 Java 資訊採 lazy-load；切換 Server 或關閉頁面會取消舊要求。
- 最小化會收進系統匣；明確結束 GUI 仍不會停止 Service。

Minecraft Server 需要相容 Java。MCSV 支援管理 Temurin Java 8／11／16／17／21／25；實際版本仍須符合核心或模組包要求。

## 6. 備份與模組包更新

- 備份與還原由 Service 執行，還原前會建立 pre-restore 回復點。
- 模組包疊代更新保留世界、玩家與必要設定，不備份可重新取得的核心。
- 候選檔案會重新檢查來源、hash、路徑及 reparse point，並使用 durable journal。
- 更新中止、崩潰、啟動失敗或健康檢查逾時會自動 rollback。

MCSV 可保護檔案與回復點，但不能保證任意第三方模組跨版本的資料語意相容性；重大升級前仍建議另外保留離線備份。

## 7. Web、iOS 與 Android

Web Host 只監聽 `127.0.0.1`。公開入口應使用受控 Tailscale Funnel，或自行設定的 Cloudflare Named Tunnel；不要改成 `0.0.0.0`、UPnP 或路由器 Port Forward。

- iPhone／iPad：以 Safari 開啟 HTTPS 網址後選「加入主畫面」。
- Android：側載 `mobile\Muhun-MCSV-Remote.apk`；package 為 `com.muhun.mcsv.remote`、版本 1.0.3，APK 已驗證 v2／v3／v4。
- 登入使用電腦端建立的帳號；記住裝置使用 Secure、HttpOnly、SameSite Cookie，不在網頁腳本保存密碼。
- Web 離線時不會排隊啟動、停止或其他 mutation。

Tailscale、Cloudflare、Discord 與第三方目錄需要各自帳號、網路與服務可用性。MCSV 不保證外部網址、免費方案或服務永久不變。

## 8. 帳號、權限與通知

- 支援 Owner、Admin、Operator、Viewer，以及全域／逐 Server grant。
- 後端每次 mutation 都會重新驗證登入、角色、Server scope、Origin、CSRF 與冪等鍵；隱藏按鈕不是授權。
- 最後一個可用 Owner 不可刪除、停用或降級。
- PIN、Session、Tunnel token 與 Discord Webhook 不進 API、audit 或一般 log；外部秘密存於 DPAPI Vault。
- 通知使用 SQLite outbox、去重、節流與有界重試，支援繁體中文及英文內容。

## 9. 產品更新

1.0.3 內嵌的 stable 更新基底為：

```text
https://your-device.example.ts.net/mcsv-updates/
```

目前該位置尚未部署正式 manifest、signature 與 ZIP，回應 404。因此「檢查更新」會安全失敗；重新產生網域或停用驗證都不是修正方式。只有維運者實際部署已簽署檔案後，自動下載才會生效。

更新會驗證固定 HTTPS host、RSA-PSS manifest、公鑰 pin、ZIP／逐檔 SHA-256，再以外部 Updater 做 A/B 切換。1.0.3 另加入 durable pending、terminal receipt、崩潰可重入及有界舊版本／套件保留；active、pending、journal 與目前通道候選不會被清理。

## 10. 解除安裝

以系統管理員 PowerShell 7 執行：

```powershell
& '<install-or-release-dir>\Uninstall-MuhunMcsv.ps1'
```

預設移除程式、Service 與捷徑，但保留 `%ProgramData%\Muhun\MCSV`。只有確定不要任何 Server、備份、帳號及秘密時才使用 `-RemoveData`。

本次正式驗收沒有在目前主機執行真實升級或解除安裝；現行 1.0.0 Service 與既有 Server 都保持不變。

## 11. 常見問題

- **安裝器顯示發布者不受信任**：先核對本文件的完整憑證 SHA-256，再信任發行目錄內 `publisher.cer`；不要關閉簽章或改用別處同名憑證。
- **按鈕仍停用**：確認實際 Windows Service 已升級到 1.0.3／API 1.5，並重新開啟 GUI；只直接執行新 GUI 不會升級 Service。
- **關閉 GUI 後 Server 還在跑**：這是正式架構的預期行為。請在 GUI／Web 明確停止 Server，或由系統管理員停止整個 Windows Service。
- **更新檢查 404**：正式更新站尚未部署；目前只能使用本機已簽署 1.0.3 安裝器升級。
- **外網無法開啟 Web**：檢查 Tunnel 帳號、路由所有權、HTTPS Origin 及本機 Web 狀態；不要公開本機 listener。
- **檔案被修改**：重新執行 `Test-MuhunMcsvRelease.ps1`。任何 hash、簽章或 inventory 不符都應停止安裝。

正式驗證數字與隔離執行證據見[測試報告 1.0.3](測試報告-1.0.3.md)。
