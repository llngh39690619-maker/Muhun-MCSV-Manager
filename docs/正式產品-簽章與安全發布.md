# Muhun MCSV Manager 正式簽章與安全發布

這套流程同時使用兩種互不取代的簽章：

- **Windows Authenticode**：簽署 GUI、Service、Updater 與安裝／解除安裝 PowerShell，供 Windows 驗證發布者、檔案完整性及可信時間戳。
- **RSA-PSS-SHA256 更新簽章**：簽署原始 UTF-8 `update-manifest.json` 與 `release-manifest.json`，供 MCSV Updater、安裝程式及離線驗證器固定信任指定公鑰。
- **ECDSA P-256 Provider 簽章**：使用獨立第一方 Provider 金鑰，對 `.mcsvp` 長度與 SHA-256 的 domain-separated payload 簽章；不可與產品更新簽章互換。

逐檔 SHA-256 不是簽章，也不能單獨證明發布者。`SHA256SUMS.txt` 必須與已簽署 manifest 完全一致才會被接受。

## 信任模式

### `self-signed-local`

專案可自行建立 4096-bit RSA Code Signing 憑證，不需要購買憑證。它可以證明「檔案仍由同一把專案私鑰簽署」，但 Windows、瀏覽器及 Microsoft SmartScreen **不會自動公開信任**它。

正式安裝程式採 fail-closed：自簽憑證只有在該 Windows 電腦已由管理員或組織原則明確信任時，`Get-AuthenticodeSignature` 回報 `Valid` 才允許安裝。流程不會自動加入 Root、TrustedPeople 或 TrustedPublisher，也不會關閉 SmartScreen、降低 Execution Policy 或使用 `Unblock-File`。

### `public-ca`

公開散發時應更換為受 Windows 信任的公開 Code Signing CA 憑證，並逐步累積 SmartScreen 信譽。公開 CA 憑證也不等於立即取得 SmartScreen 信譽；本專案不嘗試繞過或偽造該機制。

兩種模式都要求：RSA 至少 3072 bit、Code Signing EKU、SHA-256 Authenticode、可信時間戳、RSA-PSS-SHA256 detached manifest，以及相同發布者憑證指紋。

## 一次性建立專案自簽身分

私鑰目錄必須位於原始碼 repository 之外，並放在具備備份與存取控管的位置。下列命令只建立檔案，不會安裝或信任憑證：

```powershell
pwsh -NoProfile -File .\scripts\New-MuhunMcsvSigningIdentity.ps1 `
  -OutputDirectory 'D:\Muhun-Private\MCSV-Signing'
```

輸出內容：

- `muhun-mcsv-release-signing.pfx`：4096-bit RSA 私鑰與 Code Signing 憑證。
- `pfx-password.dpapi`：以目前 Windows 使用者 DPAPI 保護的隨機 PFX 密碼，不是明文。
- `muhun-mcsv-release-signing.cer`：可公開的憑證。
- `update-signing-public-key.json`／`.pem`：可嵌入 Updater 的 RSA 公鑰。
- `signing-identity.json`：Key ID、指紋與信任限制，不含密碼。
- `provider-signing-private-key.pem`：AES-256-CBC／PBKDF2 加密的 P-256 PKCS#8 私鑰。
- `provider-key-password.dpapi`：由目前 Windows 使用者 DPAPI 保護的隨機 Provider 私鑰密碼。
- `provider-signing-public-key.pem`／`provider-signing-identity.json`：可發布的 Provider 公鑰與指紋中繼資料。

目錄 ACL 只保留建立者與 `SYSTEM`。PFX、DPAPI 密碼檔與任何備份都不得提交到 Git、同步到公開雲端或附在錯誤報告。DPAPI 檔只能由原建立者在同一 Windows 使用者範圍解開，因此必須另有安全、離線且加密的災難復原備份。

## 產生正式發行目錄

若要從 solution 開始執行完整 Release build、warnings-as-errors、全部測試、三個 self-contained publish、簽章及封裝，可直接使用：

```powershell
pwsh -NoProfile -File .\scripts\Build-MuhunMcsvFormalRelease.ps1 `
  -Version '1.0.0' `
  -OutputDirectory 'D:\Example-MCSV-Releases\1.0.0' `
  -PackageBaseUri 'https://updates.example.com/mcsv/' `
  -SigningIdentityDirectory 'D:\Muhun-Private\MCSV-Signing' `
  -PublisherTrustMode self-signed-local
```

它只會在 repository 的 `artifacts/formal-staging` 建立有專用 marker 的暫存目錄；成功後只清除該次暫存。正式發行輸出仍須是全新或空白目錄。

也可將已由其他受控建置系統完成的乾淨 payload 交給下一節的低階封裝腳本。

輸入 payload 必須是全新正式 Release publish，至少包含：

```text
service-win-x64/Muhun MCSV Service.exe
gui-win-x64/Muhun MCSV Manager.exe
updater-win-x64/Muhun MCSV Updater.exe
```

執行：

```powershell
pwsh -NoProfile -File .\scripts\New-MuhunMcsvRelease.ps1 `
  -PayloadDirectory 'D:\Example-MCSV-Build\payload' `
  -BuiltinProviderDirectory 'D:\Example-MCSV-Build\builtin-provider-win-x64' `
  -MobileArtifactDirectory '.\artifacts\android-release-staging\mobile' `
  -AndroidApkSignerPath '..\tooling\android-sdk\build-tools\36.0.0\apksigner.bat' `
  -AndroidAapt2Path '..\tooling\android-sdk\build-tools\36.0.0\aapt2.exe' `
  -OutputDirectory 'D:\Example-MCSV-Releases\1.0.0' `
  -Version '1.0.0' `
  -Channel stable `
  -PackageBaseUri 'https://updates.example.com/mcsv/' `
  -SigningIdentityDirectory 'D:\Muhun-Private\MCSV-Signing' `
  -PublisherTrustMode self-signed-local
```

流程只接受全新或空白 OutputDirectory，且依序完成：

1. 拒絕 reparse point、不安全路徑、保留檔名、超過 2 GiB 或超過 10,000 個檔案的輸入。
2. 對 GUI、Service、Updater、第一方 Provider EXE 與三個管理腳本做 SHA-256 Authenticode 和時間戳。
3. 建立 `muhun.catalog.mcsvp`、逐檔 Provider manifest、P-256 detached signature 與固定 bootstrap descriptor。
4. 以 pinned Android Build Tools 重新驗證 APK v2／v3 簽章、唯一簽署憑證、package/version，再納入其憑證指紋中繼資料；APK 不會塞入 Windows 更新 ZIP。
5. 建立版本化 Windows ZIP 與 `installed-version.v1.json`。
6. 產生逐檔 SHA-256、更新 manifest、RSA-PSS detached signature 及發行 manifest。
7. 呼叫獨立驗證器重新讀取所有檔案、兩層 ZIP entry、三種簽章、憑證、公鑰與 manifest。
8. 任一步失敗就留下 `RELEASE-FAILED.txt`，該目錄不可安裝或發布。

`PackageBaseUri` 必須是無帳密、使用預設 443 的 HTTPS 目錄 URL。正式發行需要可用時間戳服務；不可用未時間戳的簽章代替。

## 發布前離線重驗

```powershell
pwsh -NoProfile -File .\scripts\Test-MuhunMcsvRelease.ps1 `
  -ReleaseDirectory 'D:\Example-MCSV-Releases\1.0.0'
```

正式安裝前不可使用 `-AllowUntrustedSelfSigned`。該 switch 只供發布機在自簽憑證尚未建立本機信任時，檢查 detached RSA-PSS、精確憑證 pin、時間戳存在與所有雜湊；安裝程式本身永遠要求 Authenticode `Valid`。

## 安裝、升級與回復

只能執行發行目錄內已由相同發布者簽署的 `Install-MuhunMcsv.ps1`。安裝程式會先驗證自己、發布者憑證、兩份 RSA-PSS manifest、所有 SHA-256 與必要 Authenticode，再將簽署檔案複製到新版本目錄。

升級會保留舊版本。新 Service 路徑、`active-version.v1` 或啟動後存活檢查失敗時，安裝程式會還原原 Service binary path、原 active version 與原運行狀態，再移除未完成的新版本。Updater 也要求新舊版本都有 `installed-version.v1.json`，所以缺少可驗證回復點時不會先切換 active pointer。

## 金鑰輪替與撤銷

- 私鑰疑似外洩時，立即停止發布；不要用同一把私鑰再簽「修復版」。
- 新公鑰必須先由仍可信的舊金鑰簽署並加入產品的受信任 key set，完成過渡後才移除舊 key。
- 公開 CA 憑證應同時走 CA 撤銷程序；自簽憑證則由組織原則移除本機信任。
- 公開 release 只可嵌入 `.cer`、SPKI 或 `update-signing-public-key.json`，絕不可嵌入 PFX 或 DPAPI 密碼檔。
